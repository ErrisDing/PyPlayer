## 大文件分块播放无缝切换 (2026-04-25)

### 问题描述

大音频文件（>50MB 或 >30分钟）使用分块（chunk）播放时，每60秒出现一次可闻的音频中断。

### 问题分析

原 `_playback_worker_chunked()` 实现存在以下问题：

1. **每个chunk创建新stream** - 旧实现为每个chunk创建新的 `sd.OutputStream`，stream的创建和启动存在延迟
2. **串行处理** - 播放完chunk N后才加载chunk N+1，造成间隙
3. **位置追踪错误** - seek定位时从chunk起始位置播放，而非定位点

### 解决方案

#### 1. 单一stream连续播放

使用单个 `OutputStream` 播放整个文件，在callback内无缝切换chunk数据：

```python
# 创建单一stream
self._current_stream = sd.OutputStream(
    samplerate=sample_rate,
    channels=channels,
    dtype='float32',
    callback=audio_callback,
    blocksize=4096  # 较大的blocksize提高稳定性
)
```

#### 2. 双缓冲预加载

在播放chunk N时，后台线程预加载chunk N+1：

```python
# 新增字段
self._chunk_buffer_lock = threading.Lock()
self._next_chunk_data: Optional[np.ndarray] = None
self._next_chunk_index: int = -1
self._current_chunk_data: Optional[np.ndarray] = None
self._current_chunk_index: int = -1
self._chunk_offset: int = 0  # 用于位置追踪
```

#### 3. Callback内无缝切换

```python
def audio_callback(outdata, frames, time_info, status):
    written = 0
    while written < frames:
        remaining_in_chunk = len(chunk_data) - current_frame[0]
        
        if remaining_in_chunk <= 0:
            # 尝试从预加载缓冲区获取下一个chunk
            if self._switch_to_next_chunk(samples_per_chunk):
                current_frame[0] = 0
                self._chunk_offset = 0
                continue
            else:
                # 播放结束
                outdata[written:] = 0
                raise sd.CallbackStop()
        
        # 写入音频数据
        to_write = min(frames - written, remaining_in_chunk)
        outdata[written:written + to_write] = chunk_data[start:end] * self._volume
        current_frame[0] = end
        written += to_write
```

#### 4. 正确的位置追踪

修复seek定位问题，确保从正确位置播放：

```python
# 位置计算：chunk起始 + chunk内偏移 + 当前帧
self._position_samples = min(
    self._current_chunk_index * samples_per_chunk + self._chunk_offset + current_frame[0],
    self._total_samples
)

# get_position 区分chunked模式
def get_position(self) -> float:
    if self._use_chunked_loading:
        with self._playback_lock:
            return self._position_samples / self._sample_rate
    # ... 普通模式逻辑
```

## 暂停/恢复播放断点续播修复 (2026-04-25)

### 问题描述

点击暂停后再点击播放，实际播放的是下一首歌曲，而不是从暂停位置继续播放（断点续播失败）。

### 问题分析

问题出在 `core/player.py` 中的播放线程监控逻辑存在竞争条件：

1. **`pause()` 方法的竞争条件**：先停止音频流，再设置 `_pause_event`。这导致播放线程在 `_pause_event` 设置之前就检测到流已停止，从而跳出监控循环并触发 `track_ended` 回调，播放下一首。

2. **监控循环检查顺序错误**：`_playback_worker` 和 `_playback_worker_chunked` 中，先检查 `stream.active` 再检查 `_pause_event`。当暂停导致流停止后，循环会先检测到流不活跃而退出，跳过了暂停处理逻辑。

### 解决方案

#### 1. 修复 `pause()` 方法 - 先设置事件再停止流

```python
def pause(self) -> None:
    # Set pause event FIRST to prevent race condition with playback worker
    self._pause_event.set()

    with self._playback_lock:
        # Then record position and stop stream
        if self._current_stream and self._current_stream.active:
            elapsed_samples = int((time.time() - self._play_start_time) * self._sample_rate)
            self._pause_position_samples = self._position_samples + elapsed_samples
            self._current_stream.stop()
        # ...
```

#### 2. 修复监控循环 - 先检查暂停事件再检查流状态

**`_playback_worker` 修复：**

```python
# Monitor playback state
while not self._stop_event.is_set():
    # Check pause event FIRST before checking stream activity
    if self._pause_event.is_set():
        # Handle pause...
        # Wait for resume or stop
        while self._pause_event.is_set() and not self._stop_event.is_set():
            time.sleep(0.05)

        if not self._stop_event.is_set() and not self._pause_event.is_set():
            # Resume: exit this thread, resume() will start a new one
            return
        break

    # Now check if stream stopped (only after checking pause)
    if self._current_stream is None or not self._current_stream.active:
        break

    time.sleep(0.05)
```

**`_playback_worker_chunked` 同样修复。**
